DECISION CRITERIA

4 Factors to Consider Before Choosing an ML Model

Examiner Question: "What factors did you consider before choosing your algorithm?"

1. Target Variable Type
Classification vs Regression
If the target is discrete categories (Placed vs Not Placed), use Classification.
If the target is a continuous number (Salary Package in LPA), use Regression.
Say to Examiner: "Our target is binary discrete (0 or 1), so we framed this as Supervised Classification."
2. Data Format & Structure
Tabular vs Unstructured
For tabular datasets (CGPA, coding test %, backlogs count), Tree Ensembles (Random Forest / Gradient Boosting) are state-of-the-art.
Neural Networks are meant for raw unstructured data (images/audio).
Say to Examiner: "Tree ensembles consistently outperform deep learning on tabular data under 50k rows."
3. Linearity vs Non-Linearity
Compound Decision Boundaries
Placement criteria are non-linear: a student with 9.5 CGPA but 2 active backlogs gets disqualified.
Linear models cannot draw curved multi-condition boundaries; Decision Trees capture these compound IF-ELSE rules naturally.
Say to Examiner: "Placement criteria are driven by compound logic which requires non-linear models."
4. Overfitting Risk
Single Tree vs 200 Trees
A single Decision Tree memorizes training noise and fails on unseen students (high variance).
Ensemble models combine 200 trees to average out individual mistakes and generalize reliably.
Say to Examiner: "We used an ensemble of 200 trees to eliminate single-tree overfitting."

EVALUATION FOUNDATION

The Confusion Matrix: The 4-Quadrant Report Card

Every evaluation metric (Accuracy, Precision, Recall, F1) originates from these 4 outcomes:

1. True Positive (TP)
CORRECT SUCCESS HIT
Model predicted: READY (1) | Actual: READY (1)
The model correctly identified a student who successfully cracked campus placement drives.
2. False Positive (FP) - Type I Error
DANGEROUS FALSE ALARM
Model predicted: READY (1) | Actual: NOT READY (0)
Dangerous: An unprepared student was falsely flagged as ready, attended interviews without prep, and got rejected.
3. False Negative (FN) - Type II Error
MISSED TALENT
Model predicted: NOT READY (0) | Actual: READY (1)
Missed opportunity: The student was actually placement-ready, but the system incorrectly flagged them as not ready.
4. True Negative (TN)
CORRECT WARNING
Model predicted: NOT READY (0) | Actual: NOT READY (0)
Accurate diagnosis: The model recognized skill deficiencies so the student could receive remedial training early.
CORE METRICS

Accuracy vs Precision vs Recall: Clear Formulas & Meaning

Examiner Question: "What is the difference between Precision, Recall, and Accuracy?"

ACCURACY
Overall Correctness
(TP + TN) / Total
Percentage of total correct predictions out of all tested students.

The Trap: If 95% of students fail and the model blindly predicts 'Fail' for everyone, Accuracy is 95% but model is useless!
PRECISION
Prediction Quality
TP / (TP + FP)
Out of all students the model marked as 'Ready', how many were truly ready?

Priority: When False Positives are costly (e.g., direct referral to top-tier companies).
RECALL (Sensitivity)
Coverage / Completeness
TP / (TP + FN)
Out of all truly ready students in college, how many did the model successfully catch?

Priority: When False Negatives are dangerous (e.g., catching struggling students who need training).
BALANCED PERFORMANCE

F1-Score: Why Do We Use Harmonic Mean?

Examiner Trick Question: "Why Harmonic Mean instead of Simple Average?"

Arithmetic Mean Conceals Flaws
Suppose a model has Precision = 100%, but Recall = 0% (missed every single ready student):
• Simple Average = (100% + 0%) / 2 = 50% !!
(Gives a false impression of moderate quality for a completely broken model).
Harmonic Mean Exposes Severe Flaws:
• F1 = 2 × (1.0 × 0.0) / (1.0 + 0.0) = 0.0% !!
(Heavily penalizes extreme values; F1 is high ONLY when both metrics are high).
Our Model's F1 Benchmark
F1 = 2 × (Precision × Recall) / (Precision + Recall)
• Gradient Boosting F1-Score: 96.10%
• Accuracy : 96.08%
• Precision : 96.20%
• Recall : 96.00%
• ROC-AUC : 0.985
Say to Examiner: "Our F1-score of 96.1% confirms that both False Positives and False Negatives are minimized."
PRACTICAL MATH

Live Viva Calculation: 4 Simple Steps on Paper

Examiner: "Take a pen and paper. If TP=45, FP=5, FN=5, TN=45, calculate all metrics."

Given Confusion Matrix
• TP (True Positives) = 45
• FP (False Positives) = 5
• FN (False Negatives) = 5
• TN (True Negatives) = 45
----------------------------
Total Students Tested = 100
Step-by-Step Live Math
1. Accuracy = (45 + 45) / 100 = 90 / 100 = 90.0%
2. Precision = 45 / (45 + 5) = 45 / 50 = 90.0%
3. Recall = 45 / (45 + 5) = 45 / 50 = 90.0%
4. F1-Score = 2 × (0.90 × 0.90) / (0.90 + 0.90) = 90.0%

4 Core Questions Asked by Examiners & Exact Answers

Memorize these 4 direct lines to answer questions with total confidence:

Q1: Why did you choose Gradient Boosting?
"Sir, placement rules are non-linear (e.g., high CGPA with active backlogs leads to rejection). Tree ensembles naturally capture compound IF-ELSE criteria without requiring feature scaling, reaching 96.08% accuracy."
Q2: If accuracy is 95%, is the model always good?
"No, Sir. On imbalanced data where 95% fail, a naive model predicting Fail for everyone gets 95% accuracy with 0% Recall. That is why we evaluate F1-score and ROC-AUC."
Q3: How did you prevent overfitting?
"Sir, we used an ensemble of 200 trees rather than a single tree, restricted tree depth to 5 (max_depth=5), and used an 80-20 Stratified train-test split."
Q4: Which feature influenced predictions the most?
"Sir, Active Backlogs was the strongest negative factor (0 backlogs is mandatory for most campus drives), while Coding Proficiency and Technical Score were the strongest positive drivers."
